# Экспертная оценка безопасности NoteLab

## 1. Объект исследования

Объектом исследования является учебное веб-приложение NoteLab, разработанное на языке Python.
Приложение предназначено для создания и просмотра текстовых заметок. Веб-интерфейс работает
через локальный HTTP-сервер на порту 8080. Приложение развёрнуто в виртуальной машине
Linux Mint.

## 2. Область исследования

Для получения информации о сетевых диапазонах GitHub использовался GitHub Meta API.
Полученные через Meta API IP-адреса относятся к инфраструктуре GitHub и не являются
личным IP-адресом пользователя.

Сетевой анализ выполнялся не в отношении инфраструктуры GitHub, а только в отношении
собственного лабораторного сервиса NoteLab, работающего на виртуальной машине (10.0.2.15).

## 3. Анализ с помощью Nmap

С помощью Nmap выполнено сканирование TCP-порта 8080 виртуальной машины.
Подтверждено наличие открытого порта 8080, используемого веб-приложением NoteLab.
Определена версия сервиса: BaseHTTP/0.6 Python/3.10.6.

Дополнительно NSE-скриптом http-security-headers установлено, что заголовки безопасности
(HSTS, CSP, X-Frame-Options) не отдаются сервером.

Открытый порт в рамках лабораторной работы не является критической уязвимостью,
поскольку он открыт намеренно для запуска учебного приложения.

## 4. Анализ с помощью Masscan

Для дополнительной проверки сетевой поверхности использован Masscan.
Скорость сканирования ограничена значением 100 пакетов в секунду.
При сканировании собственной виртуальной машины открытый порт 8080 данным инструментом
не был обнаружен. Это связано с особенностями сетевого стека VirtualBox NAT.
Наличие сервиса подтверждено сканером Nmap.

## 5. Анализ с помощью Nikto

Сканер Nikto обнаружил отсутствие заголовка X-Frame-Options — риск clickjacking.
Рекомендуется добавить заголовок X-Frame-Options: DENY на уровне веб-сервера или
reverse-proxy.

## 6. Статический анализ Horusec

Horusec выполнен без Docker (флаг -D). Анализ исходного кода проекта NoteLab
критических уязвимостей и утечек секретов не выявил. Это положительный результат,
однако дополнительная ручная проверка кода всё равно рекомендуется.

## 7. Общая оценка

Учебная система имеет ограниченную область применения и используется только
в лабораторной среде. Основной обнаруженный сетевой объект — открытый порт 8080,
необходимый для работы приложения.

## 8. Рекомендации

1. Закрывать неиспользуемые сетевые порты.
2. Ограничивать доступ к служебным интерфейсам.
3. Использовать HTTPS при размещении приложения в публичной сети.
4. Настраивать защитные HTTP-заголовки (X-Frame-Options, CSP, HSTS).
5. Не хранить пароли и ключи в исходном коде.
6. Исключать конфиденциальные файлы из Git с помощью .gitignore.
7. Регулярно проверять проект средствами статического анализа.
8. Повторять сетевое сканирование после изменений.

## 9. Вывод

В ходе работы проведён комплексный анализ учебного проекта NoteLab: проверена сетевая
доступность, определён используемый порт, выполнено дополнительное сканирование
Masscan и Nikto, исходный код исследован Horusec. Результаты сохранены
в структурированном виде и объединены в единый датасет.
